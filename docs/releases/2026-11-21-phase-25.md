# CaroCRM — Phase 25 AI capability parity (release note)

> **Date:** 2026-11-21
> **Scope:** `plans/PLAN_Phase_25_AI_Capability_Parity.md` — AI capability parity against Twenty v2.59.
> Phase 25 is **complete as a phase**: every sub-phase 25.0–25.12 is implemented.
> **Release decision:** **GO for alpha/pilot — AI capability only.** **NO-GO for production** — unchanged
> from the Phase 23 and Phase 24 reviews (`docs/quality/phase-23-security-release-review.md`,
> `docs/quality/phase-24-12-release-review.md`); see §5.
> **Not a claim of:** production readiness, full Twenty parity or full EspoCRM parity.

## 1. What Phase 25 is

Phase 25 turns the existing AIAgents / CRM Chat engine into a parity-level product surface. It starts from a
capability matrix written against Twenty's shipped value (not its alpha packaging), pins a least-privilege
execution principal, and then delivers the missing capabilities one sub-phase at a time: reusable versioned
skills, a bounded AI action inside the workflow engine, watched-field and condition triggers, bounded
multimodal input, grounded web search, page-aware chat, installation-level cost visibility, a deterministic
golden evaluation gate — and, last, an honest review that says what is at parity, what is better, what is
deliberately skipped and what remains blocked.

**Product boundary (owner decision, 2026-11-13, reaffirmed): still single-tenant — one deployment serves one
organisation.** No workspace, tenant id, per-tenant retrieval, credits, billing, personal AI allowance or
hosted multi-tenant AI was added by this phase. Twenty's alpha skills/agents and beta MCP declarations were
never treated as shipped parity requirements; CaroCRM's MCP-compatible adapter and fail-closed ACL remain the
stronger side.

**The canonical claim source is `docs/architecture/ai-capability-matrix.md`.** This note summarises; it does
not replace it.

## 3. Behaviour changes a reader can notice

- **The assistant knows which page you are on.** In CRM Chat, the client sends the identifiers of the record in
  view; the server resolves them under the caller's own ACL and drops anything the caller may not read. A
  "summarise my interactions with this person" question works from a contact page and is refused from an
  unrelated one.
- **Agents are pinned to a person.** A published agent records which identity its runs act as
  (`requesting_user` or `publisher`), and every run event carries the effective principal and the pinned
  version. An autonomous run cannot borrow somebody else's role.
- **Skills are versioned and cannot execute code.** A published agent pins exact skill versions; the skill
  text is composed under the operating rules and recorded in the run timeline. There is no code-defined agent
  and no skill can run shell or SQL — an owner decision, not an omission.
- **A workflow step can ask an agent.** One bounded `runAgent` action, with strict parameters, an approval
  expectation that can only tighten the policy, and an idempotent run attributed to the workflow run.
- **The assistant can search the web, once, under your rules.** One `web_search` tool over an endpoint you
  configure; off by default, fail-closed, SSRF-checked on every call, and every hit is treated as untrusted
  data and cited with its URL and retrieval time.
- **You can see what the AI cost.** A usage view answers "which agent, model and trigger spent what, over
  which window" from the screen and from a CSV export, and warns you before a soft limit stops work.
- **The evaluation suite is a gate, not a promise.** A versioned dataset (English and Vietnamese) with a
  tool-routing accuracy metric and a floor that may only rise, enforced inside the existing nightly lane: a
  broken tool grant or a read-only prompt that reaches a write tool fails the gate.

## 4. Migration requirements

Phase 25 added **three additive migrations**: `098_phase25_agent_skills.sql` (the `ai_agent_skills` table),
`099_phase25_workflow_trigger.sql` (the `workflow` value added to the run-trigger check) and
`100_phase25_web_search_citations.sql` (the `approved_external_source` citation source and a nullable
`retrieved_at`). No row, table or column is removed or rewritten, and no backfill is needed. 25.9, 25.10,
25.11 and 25.12 need no migration at all: the dataset is a repository file, the gate reads the existing tool
registry, and the review is a document. No extra database was created.

## 5. Release decision

**GO for alpha/pilot, for the AI capability only.** The AI surface is coherent, documented and traceable to
tests that exist in the repository; `docs/quality/phase-25-release-review.md` records the per-row verdict, the
residual P1/P2 risks with their owners and the exact conditions.

**NO-GO for production — unchanged.** The blockers are owner and deployment decisions, not AI-capability ones:
G80/G81 (no installed encrypted off-host backup and no completed restore drill), the unanswered
distribution/licence question, and the unsigned High/Critical exceptions in
`docs/security/exception-register.md` §5.

The alpha/pilot carries the four conditions of the Phase 23 review §8 (synthetic or demo data, deployment
secrets from the secret store, no distribution outside the organisation, and a nightly gate repeated each
night) plus three AI conditions: the AI features stay feature-gated **off** by default, the pilot uses the
fake provider or a provider the operator accepts the cost of, and nobody claims model-backed routing quality.

## 6. Known limitations

- The nightly gate has not been executed against the Phase 25 suites; every "source-verified" row in the
  review is unproven at runtime until the developer runs it.
- The model's own routing on free-form prompts is unmeasured. The golden gate scores a deterministic intent
  contract (G102), which is the honest claim in a lane with no model.
- 24 provider presets are configuration, not verified adapters; no live vendor call has been made.
- Cron expressions are interpreted in the worker process timezone, not the agent owner's IANA zone.
- Assignable agent roles are missing: the principal is pinned to a user identity instead.
- Credits, billing and per-seat allowances, workspace agents, model-backed retrieval, code-defined agents,
  Twitter/X search and a new MCP surface are **deliberate skips**, recorded in the matrix and the decision
  record — not gaps.
