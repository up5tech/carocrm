# CaroCRM — Phase 22 hardening release notes

> **Date:** 2026-10-29
> **Scope:** the Phase 22 hardening workstream, not a feature release and **not** a claim of complete
> EspoCRM parity. Only the verified scope below is claimed.

## 1. Behaviour changes

### Security and correctness fixes

- The default JWT secret is refused in production; the default is only a development fallback (G9).
- Campaign reports answer to the campaign's record read grant and mask recipients the caller cannot
  open (G31); a replayed attribution outcome no longer double-counts (G32).
- The connector worker doors are reachable only by the worker, every write door has a capability
  check, a webhook's domain-claim flag survives, and a bounded sync cannot advance its checkpoint past
  records it did not apply (G40–G45).
- An unexpected error sends a generic 5xx body, never the driver/connector text (G54); the SPA renders
  field errors and dates through the shared helpers (G55–G60).
- The MCP-shaped AI tool door cannot commit an approval-class write without a decision (G35).
- Payment provider event ids are scoped by provider (G20); the duplicate lead-score job collapse uses
  the real `running` status (G22); an AI approval pins the target record version and refuses a moved
  target (G72).

### Reliability and resilience

- Queue and outbox retries use equal jitter (G15); an outbox claim is a lease, so a crashed worker's
  event is reclaimed instead of stuck forever (G70).
- Every hash-storing provider inbox detects a redelivery that reuses an id with a different body and
  records the mismatch instead of silently discarding it (G19).
- Provider timeouts, 429/5xx, expired credentials, malformed payloads, duplicate/out-of-order delivery,
  worker interruption, approval expiry and storage failures have deterministic tests (22.18).
- The outbox/job snapshot (`AdminInternal/action/operations`) and the platform runbook make the
  failures diagnosable; correlation ids run from the HTTP request through the outbox/job to the worker
  log (22.21).

### UI/API consistency

- Shared loading, empty, error and permission-denied states; consistent date/number formatting;
  actionable retry states; accessible skeletons and modal behaviour (22.15/22.16). Browser critical
  paths are covered by the Playwright spec with sanitized fixtures (22.16).

## 2. Migration requirements

Apply migrations **before** starting the new code (`pnpm db:migrate`; the API also applies them at
boot). The Phase 22 additions are forward-only and additive:

| Migration | Change |
|---|---|
| `083_phase22_payment_provider_event_dedup.sql` | Unique index on payment provider event id (superseded in part by 085). |
| `084_phase22_marketing_attribution_dedup.sql` | Partial unique index for attribution replay. |
| `085_phase22_payment_event_key_scoped.sql` | Drops the redundant unscoped payment-event index; the `(provider, providerEventId)` index from 024 remains. |
| `086_phase22_outbox_correlation.sql` | Adds nullable `outbox_events.correlation_id` and a partial index. |

Do not roll back by dropping columns/tables. A failed migration is a stop-the-line event; use a
forward fix or the restore procedure (which is **not yet rehearsed**, see §4).

## 3. Operational actions

- Set real secrets: `JWT_SECRET` (production), `ENCRYPTION_KEY`, provider credentials. The default JWT
  secret is refused only in production; an alpha install must still set one.
- External effects are off unless configured: `MAIL_TRANSPORT` defaults to `none`, AI execution is off
  by default, the marketing webhook secret is blank and fails closed, and unconfigured providers do
  not become fake successes.
- Configure the backup policy **before** carrying real customer data: `pnpm backup` (pg_dump + files,
  checksums, gpg encryption required by default, 700/600 permissions, opt-in retention), then add the
  deployment cron/off-host copy/recipient key/freshness alert. Run `pnpm verify:backup <dir>` on an
  NDJSON artifact. Phase 22.25 made the job safe; the schedule/off-host evidence is still missing.
- Approve RPO/RTO and run the restore drill in an isolated approved environment; until then there is
  no restore evidence (G80/G81).
- The scheduled CI gate runs nightly (`quality-gate.yml`); it is DB-free by design. Run `pnpm verify`
  locally before merging.

## 4. Known issues and residual risk

Open items are tracked with owner/scope/review in `docs/quality/known-gaps.md`. The release-relevant
ones:

- **G80/G81 (High/blocked):** no restore drill, no approved RPO/RTO; no deployment backup schedule/
  off-host copy/recipient key; the demo artifact is partial and stale (permissions fixed in 22.25).
  **Production release is blocked on this.**
- **G1/G6/G8 (Medium):** no generated OpenAPI document; many domain events have no consumer (accepted);
  the shared core imports two domain modules (allow-listed).
- **G21/G23/G47/G48/G50/G51/G53 (Medium):** no job retry/discard API, dead-letter "replay" does not
  re-run, token refresh is not wired, rate-limit/retry ownership is open, mapping picks a connection by
  name order, OAuth redirect URI is not compared, and deferred deliveries are not retried.
- **G37/G38/G39 (Medium/Low):** Case `own`-scope create, CRM Chat `readTools` not enforced, turn
  sources not re-authorized (security exceptions documented in the 22.17 phase doc).
- **G63/G64/G65/G66/G67/G68 (Medium/Low):** SPA-only guard on `/admin`, raw `error.message` sites,
  client-side home choice, browser error/empty state coverage, mouse-only column resize, module panel
  invalidation.
- **G69/G75/G79 (Low):** shared-database parallel-suite flakes; tracked with a 2026-11-15 review. The
  DB-free CI gate does not run them; they still surface in local `pnpm verify`.
- **G73/G74/G76/G77/G78 (Medium):** uncapped sequential bulk operations, no query/request deadline,
  DB-only readiness, no continuous metrics/tracing, and a scheduled-only CI (no PR gate).
- **G26/G27/G33/G36/G12–G17 (Medium/Low):** no Sales→ESignature contract, no Project↔CustomerSuccess
  read, marketing webhook signature/freshness, unreachable AI states, retention gaps, CSV import
  memory-only, dead retry config.
