## Implemented SPEC §9.6 — acting user in the system prompt

- New `apps/api/src/ai-agents/ai-agent-actor.ts`: `AIAgentActorContext`, `promptSafe()`,
  `actorPromptLines()`, and `systemPrompt()` **moved out of** `ai-agent-runs.service.ts` so the
  prompt is a pure, testable function (no API boot).
- `AIAgentRunService.actorContext(userId)` — two bounded reads (`users`, `users_teams ⟕ teams`),
  once per execution attempt, not per step. Deleted user → `undefined`, prompt omits the block;
  the run still fails on ACL, not on a prompt query.
- `promptSafe()` is the security-relevant part: a display name is user-controlled text that lands
  in the **system** message, so control chars/newlines collapse and length is capped — a hostile
  name can never start a new line, therefore never a new instruction.

  rest of the prompt. Format is contract-tested in `ai-agent-actor.test.ts`.

  `vitest.ci.config.ts` — CI has no DB) + 1 end-to-end case in `ai-agent-runs.test.ts` proving a
  run started by the restricted user and executed by admin carries the **initiator's** id, and

## Implemented 19-CHAT.21 — read tool family (registry 8 → 12)

- New `apps/api/src/ai-agents/ai-agent-periods.ts`: pure, timezone-aware token resolver
  (`this_quarter`, `last_month`, `rolling:30d`, …) → `{ label, from, to, timezone }`. Converts local
  wall clocks with a **two-pass offset correction**, which is what makes DST boundaries land right.
  16 pure cases in `ai-agent-periods.test.ts`, added to `PURE_API_TESTS`.
- New `ai-agent-directory.service.ts` (`AIAgentActorDirectoryService`): the single "who is this
  user" lookup (id, name, email, locale, timezone, teams, plus `displayNames()` for aggregate
  labels). `AIAgentRunService.actorContext()` now delegates to it — prompt and `crm_actor_context`
  can no longer disagree. Timezone falls back to `I18nService.settings().defaultTimezone`.
- Three tools in `ai-agent-tools.ts`: `crm_aggregate`, `crm_list_activities`, `crm_actor_context`.
  Fourth, `crm_cross_module`, is registered **from `crm-chat`**
  (`crm-chat-tool-contribution.ts`, `OnModuleInit`) so the DAG stays intact.
- `EntityService.linkedSourceIds()` + `PostgresRecordStore.linkedSourceIds()`: reverse
  `entity_links` lookup. Activities declare `accounts`/`contacts` on the child, so "calls about this
  account" has no forward relation; one indexed lookup then a normal ACL-filtered `list()`.
- Gotchas found while testing (worth remembering):
  - `ai_agent_tool_calls` has **no `summary` column** — the summary/result live inside `outcome`
    jsonb; the events table is `ai_agent_run_events` with `event_type`/`summary`, not `type`.
  - A role with no entity entry and no `'*'` key gets level **`no`**, so a test user with only
    `AIAgent: read` cannot read *any* entity. Need an explicit role with `read: 'all'` for the tool
    tests (and the §9.6 test only "passed" for Opportunity because it ran the tool as admin).
  - `amount` on Opportunity is `currency` → must be created as a decimal **string** (`'1000.00'`).
  - The cost-budget case earlier in `ai-agent-runs.test.ts` leaves a $1/token pricing snapshot in
    place, so every later run blows its budget before reaching a tool. The new describe block
    replaces the snapshot in its own `beforeAll`.
  - `ai_agent_runs`/tool-call cleanup is by id + marker; new records go through `entityIds`.
