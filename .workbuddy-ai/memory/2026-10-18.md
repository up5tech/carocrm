## Marketing Automation (Phase 19-MA) — closed the module

Started from `PLAN_Phase_19_Marketing_Automation.md`: the code for MA.0–MA.19 was already committed and the
plan header already claimed "complete", so the work was **verification, not scaffolding**. Gates on entry:
typecheck clean, 11 marketing suites green (198 tests). What was actually missing: the plan's §14 docs, the
§16/§17 checklists, a completion report, and any test at all for MA.10 (webhooks) / MA.13 (journey runtime).

### Defects found by writing those tests (all fixed)

1. `insert into marketing_events … on conflict (inbox_id) do nothing` → SQLSTATE 42P10, because
   `uq_marketing_events_inbox` is a **partial** index. Every accepted provider event had always failed, so
   webhook ingestion recorded nothing. Fix: repeat the predicate
   (`on conflict (inbox_id) where inbox_id is not null do nothing`).
2. Journey runtime wrote `entity_records.updated_at`; the column is **`modified_at`**. Enrollment, claim,
   step write and trace insert all failed → the journey engine could not run at all.
3. `MarketingJourneyRuntimeService.claim` only bumped `lockVersion`, so two workers could both claim and
   execute one step. Now a **lease**: the conditional UPDATE also pushes `nextRunAt` 60 s ahead; `runStep`
   no longer re-claims (that double claim was the race).
4. Webhook secret fell back to a hard-coded `"dev-marketing-webhook-secret"` → forged signatures accepted on
   any deployment without the env var. New `marketingWebhookSecret` config (empty default) and fail closed
   (`SECRET_NOT_CONFIGURED` on the inbox row); health reports the state.
5. Webhook suppression feedback ran without an identity, so a hard bounce was recorded and never applied
   (the inner `catch {}` hid it). Side effects now run under `runAsMarketingSystem`; a failure is stored as
   `processed_with_errors` + reason instead of being swallowed.
6. `POST action/journey/:id/trigger` was `@Public()` — an anonymous journey-existence oracle. Now worker
   capability (with a session) or admin.
7. `public/click` accepted `//host` and returned JSON instead of redirecting (open redirect). Now same-origin
   only (`//`, `/\`, third-party origins refused) and a real 302; `public/open` returns a 1×1 GIF.
8. `public/form/submit` returned `created`/`duplicate`/`leadId` → CRM membership oracle. Public route now
   answers `{ accepted: true }` for every outcome; the controller also passes `request.ip` so the 10/min
   limiter is per caller instead of one global bucket.

Plus one determinism fix: `MarketingAudienceService.classify` now walks candidates in `entityType:entityId`
order, so which of two same-address records wins the message no longer depends on DB row order. The send
suite's sample assertion was rewritten to assert the rule (one eligible, one duplicate) instead of a
specific winner.
