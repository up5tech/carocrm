## Phase 21 plan — in-app documentation surface

- Created `PLAN_Phase_21_Documentation.md` (1,357 lines, sections 1–21, same shape as the Phase 20
  plan) and added a `## Phase 21 — In-App Documentation and Product Help` entry to `PLAN.md` before
  `# 58. API Endpoint Inventory Plan`.
- Core decision: user-facing content lives in a **new `content/docs/<locale>/<section>/<slug>.md`**
  tree, *not* `docs/` (engineering record) and *not* i18n catalogs (chrome keys only). `en` is the
  source of truth, `vi` may be partial with a per-page fallback notice.
- Core decision: the API returns a **typed block tree** (`DocBlock`/`DocInline`), never HTML — no
  `dangerouslySetInnerHTML`, no XSS surface, internal links become router `<Link>`. Parser is
  hand-written in a new pure package `packages/docs` (no new runtime dependency; `react-markdown`
  rejected because it emits HTML and cannot enforce the subset).
- Three endpoints: `GET /Docs/tree`, `/Docs/page/:section/:slug`, `/Docs/search` — ACL-filtered per
  caller, `ETag`/`304`, in-memory per-locale index. **No migration, no table.**
- New `docs` settings document (`enabled`, `showInSidebar`, `showHelpMenu`, `externalUrl`,
  `landingPage`, `supportEmail`; read `user`, write `admin`, envelope) + one `NAVIGATION_PAGES` seed
  gated through `NAVIGATION_FEATURE_GATE` (the `crmChat`/`workspace` branch is the pattern).
- Security stance: slug is looked up in the in-memory index map and **never joined to a path**, so
  traversal is structurally impossible; a non-admin gets `403` (not `404`) on an admin page; portal
  principals get `403` everywhere; docs are descriptive, never authoritative.
- Contextual help is the adoption lever: `HelpTip` gains `docKey` (finally consuming the unused
  Phase 20 component), admin tab descriptors gain `docKey` (covers all 18 tabs in one change), and
  `PermissionDenied` gets used for a forbidden page.
- Content inventory: 38 pages — `getting-started` 4, `user` 7 P0 + 6 P1, `admin` 6 P0 + 10 P1,
  `reference` 5. A `lint` function over the shipped corpus runs in `pnpm test`, so a feature shipped
  without its page fails CI.
- Sub-phases 21.0–21.10; P0 = engine + API + reader + 17 pages, P1 = contextual help + 21 pages +
  `vi` + e2e. No frontend test runner exists, so the UI half is Playwright + manual walkthrough.
