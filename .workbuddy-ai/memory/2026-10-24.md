## CRM Chat page — UI redesign (apps/web)

Rebuilt `/crm-chat` from a stack of status cards into a chat workspace. Behaviour, hooks, API calls and
i18n keys are unchanged; only presentation moved.

- `CRMChatPage.tsx` — page head (mark + title + state pill + icon actions), `.carocrm-chat-shell` grid

- `CRMChatMessageList.tsx` — bubbles (user right/blue, assistant left/white), avatars, citation chips,
  own scroll container, sticks to bottom unless the reader scrolled up; new `conversationKey` prop.
- `CRMChatComposer.tsx` — dock frame (borderless textarea), thinking pill with animated dots replaces
  the progress Alert, footer Cancel dropped (the pill's Stop covers it), new `prefill` prop for
  suggestion chips.
- `CRMChatPromptTemplates.tsx` — inline `Empty` removed (it sat inside the composer toolbar).
- `state/i18n.ts` — added `formatClock()` and `isSameCalendarDay()`; new keys
  `web.crmChat.heroTitle|heroHint|suggestionsTitle|suggestion.*` in en + vi.

### Layout gotchas worth remembering

- Shell height is a magic `calc(100vh - 235px)` = 70 header + 48 content padding + 46 head + 14 gap +
  56 footer. Changing the page head's height breaks it; the subtitle is hidden ≤1280px so the head
  never wraps to a second row (a wrapped head makes the page scroll).
- Column flex containers that can overflow **shrink** fixed-height children (the 56px hero mark
  collapsed to a sliver). `> * { flex: none }` is required.
- Centring an overflowing column clips the first item unreachably; `justify-content: safe center` was
  not honoured in Chromium here — use auto margins on the first/last child instead.
- Short threads are bottom-anchored with a `::before { flex: 1 0 auto }` spacer, not `justify-content:
  flex-end` (which breaks scrolling to the top).

Verified in a real browser at 1440×900, 1280×800, 1100×780, 820×1000 and 390×844: no page scroll,
composer always in view. `tsc`, `eslint apps/web/src` and `vite build` all clean.

Playwright again needs `no_proxy='*' NO_PROXY='*'`, and `networkidle` never fires on this page (the
app polls) — wait for `.carocrm-chat-page` instead.

### Layout gotchas added to the list

## Documentation reader — panel, sticky rails, full width (apps/web)

The voice inbox work was committed (`c124b9c`). This turn finished the handbook surface.

- `DocsLayout.tsx` — the left rail is wrapped in `.carocrm-doc-rail-col` (the tint and the divider
  belong to the column; a background on the sticky list ends where the list ends). The grid gets
  `--no-side` when the page passes no actions, so index/search pages do not carry an empty third
  column.
- `DocsPage.tsx` — a meta row under the lede (audience chip + last reviewed) and the side actions as
  a primary button plus a two-up row (Copy link | Print) instead of three stacked full-width buttons.
- `DocsLandingPage.tsx` — each section door gets an icon and a page count.
- CSS — the reader is a white panel (border, 14px radius, subtle shadow); sticky rails moved from
  `top: 16px` to `86px` because the app header is 70px and the old offset slid them underneath it.

### Sizing decisions (the user's complaint: dead space on a large screen)

- `.carocrm-doc` is fluid now (`width: 100%`, no 1240px cap) — the page margins were the problem.
- The reading page centres its 72ch measure inside the middle column, so extra width becomes equal
  margins around the text instead of one gap before the contents rail.
- `--no-side` pages (landing, section index, search) drop the measure cap: cards and lists use the
  whole panel, only `p`/`h*` stay at 78ch. Card grids use `minmax(280px, 1fr)` so a wide screen gets
  four columns instead of five shrunken ones.

### Gotcha

- The API caches i18n catalogs in memory for the process lifetime (`ensureCatalogs`), so new keys do
  not appear until the API restarts — a browser reload alone shows the raw key.

Verified at 1920×1080, 1440×900 and 390×844. `tsc`, `eslint apps/web/src`, `vite build` clean.
Uncommitted.

### Follow-up: the reading column was too airy, the side buttons cramped

The user circled the white space between the rail and the text on a ~1240px window, and the two
squeezed half-width buttons under "Open this screen".

- The prose was centred in its column (`margin-inline: auto`), which split the slack into a hole on
  both sides. Removed: the text now sits directly after the rail.
- The panel is capped at **1100px** and centred. A fluid panel either pushes the contents rail to
  the far edge (hole after the text) or leaves a white band inside the card; 1100 is the width the
  three columns actually need (220 + measure + 208), so the interior is always full and the leftover
  is the grey page around a centred document.
- Columns: `220px minmax(0, 1fr) 208px`; prose `max-width: 78ch` (was 72ch) so it fills the middle.
- Copy link / Print became `type="text"` buttons in a vertical list with a hairline above, instead of
  two half-width buttons whose labels ellipsised at 208px.

Verified at 1240, 1440 and 1920.

### Third pass: the grey bands were the card cap, not the columns

Capping the card at 1100px put a grey band on each side of a ~1800px window. The fix is structural:

- `.carocrm-doc` is now the **white sheet**: `width: 100%` + border + radius + shadow, no max-width.
- `.carocrm-doc-grid` is the **document**: `max-width: 1180px; margin-inline: auto` inside the sheet,
  no background of its own.
- The rail column lost its tint (`#fbfcfe` + left radius) and keeps only a hairline `border-right`,
  because a tinted block that no longer touches the sheet's left edge reads as a floating panel.

Result: no grey bands at any width, and the leftover width is white-on-white inside the sheet, so the
eye sees a centred document rather than a hole. Print resets the sheet.

Verified at 1240, 1800 (page, landing, section). Lesson for this repo: for a capped reading measure,
put the *card* at 100% and the *content* in a centred inner container — capping the card itself always
trades interior gaps for grey bands.

### Fourth pass: spread the document across the sheet

The user asked for the content to spread too, not just the sheet. Removed the last two caps:

- `.carocrm-doc-grid` — no `max-width`, no `margin-inline: auto`: the three columns span the sheet
  (nav flush left, contents flush right, text takes everything between).
- `.carocrm-doc-prose` — no `max-width`: the text fills its column.
- `--no-side` pages lost their 78ch paragraph cap as well, so index prose spreads like the cards.

Trade-off to remember: at 1440 the text column lands around 85 characters per line, at 1800 around
130. If a future request asks for "readability", reintroduce a cap **on the prose only**
(`max-width: 78ch; margin-inline: auto`), never on the sheet — capping the sheet is what produced the
grey bands in the first place.

## Why "page esignature vẫn giới hạn khung" kept coming back

The source has had no width cap on `/esignature` since `0b9aa6a`, and a live measurement confirms it
(page 1132px inside a 1180px content area at 1440). The user was looking at **`apps/web/dist`**, a
manual production build from 2026-10-23 20:01 that still contained `maxWidth:1080` (the old
E-Signature wrapper) — none of the 24 Oct redesigns were in it.

Rebuilt it with `npx vite build` in `apps/web` (the folder was moved aside first — `mv dist
dist-stale-<ts>` — because `emptyDir` trips the safe-delete guard). The new `dist` has no
`maxWidth:1080` and does contain `carocrm-surface-switch`, `carocrm-reports-rail`,
`carocrm-cal-agenda`.

**Rule for this repo:** nothing serves `apps/web/dist` automatically — the API has no static handler —
so a UI change only reaches a build-based preview after `apps/web: npx vite build`. When a UI change
"did not apply", check the mtime of `apps/web/dist` before touching the source again.
