### Bonus bug found while verifying: `?q=` lost on reload

Reloading `/Account?q=…` ran the search, then an unfiltered request replaced it and the address bar
lost `q` — a shared list link showed a different list than the sender's. Cause: the free-text query
was held twice (state seeded from `urlTextQuery` + a sync effect writing it back), and a remount that
read a stale `useSearchParams()` seeded the state with `''`; the sync effect then deleted `q`.

Fix in `EntityListPage`: `const textQuery = urlTextQuery` (no state), one `setTextQuery` helper that
writes `q` and clears `offset`, and the URL-sync effect no longer touches `q` (so it cannot delete a
query it did not create). Verified: URL survives reload, 0 rows, filtered empty state with Clear.

Lesson for UI tests: assert on the specific element (`.carocrm-empty-title`), not on `body` text —
the first smoke run "passed" this check while 58 unfiltered rows were on screen.
