## 19-S.7 (quotes) completed — render + send + tests

The three open 19-S.7 items from the plan (task 5 PDF/email, task 9 tests, plus the Opportunity panel) are now done. What was added:

- `apps/api/src/sales/document/quote-document.ts` — **pure** block-model builder (`quoteBlocks`, `quoteTemplateData`, `quoteText`, `quoteTitle`, `quoteSubject`, `quoteRenderLine`). No arithmetic: it prints the engine's `LineItemTotals`/`TotalsResult` verbatim, so a rendered quote can never disagree with the quote. Absent optional facts are omitted, not printed as empty labels. Text and PDF share this model.
- `apps/api/src/sales/document/quote-send.service.ts` — `SalesQuoteSendService.render(id, templateCode?)` (the kernel `document` module, default template per `entityType`, built-in layout when none) and `send(id, input)` (issue a draft quote, then create + `EmailService.queueSend()` an `Email` linked through `parentType`/`parentId`).
  - Ordering rule: **all gates run before issuance** — `Quote: read` (view), `Email: create`, `Email: edit` (new `AclApiService` pre-check, so a caller who is refused never leaves a `sent` quote with no email), transport configured, state `draft`/`sent`, recipient resolvable, template renders. Only then is the quote issued and re-rendered so the email carries the allocated number.
  - `issued: false` in the response = a re-send of an already-`sent` quote: same document, **new** email record, no second number.
  - If the queue is unreachable *after* issuance, the stored email stays `Draft` and the error is a 500 that says so (a `ValidationError` is rethrown unchanged).
- Routes: `POST /api/v1/Sales/quote/:id/render` (read), `POST /api/v1/Sales/quote/:id/send` (wrapped in `runAsSalesInternal`). DTOs `RenderQuoteSchema`/`SendQuoteSchema` in `dto/sales-shapes.ts`; service registered in `SALES_PROVIDERS`.
- `database/seed-metadata.ts`: Opportunity gained `quotes` (oneToMany, `mappedBy: 'opportunity'`) — the 19-S.7 "source Opportunity panel". Metadata is upserted by `database/seed.ts` (`ON CONFLICT DO UPDATE`), so **no migration** is needed for a relation change.

### Test seams worth reusing

- **Sending requires a From address.** `EmailService.queueSend` refuses a message with no `fromAddress` and no default email account, so any test that exercises a send must set `process.env.MAIL_TRANSPORT = 'memory'` **and** `process.env.SMTP_FROM = '…'` *before* `bootApi()` (config is read once at boot) and restore both in `afterAll`.
- **No Redis needed:** stub the BullMQ hop with `const jobs = ctx.app.get(JobsService); jobs.enqueue = async (input) => ({ id: 'x', job: input.job, status: 'pending' }) as unknown as JobView;`. Assert on the durable side effects (Email record + ledger + quote state) instead.
- `process.env` is shared across suites because the root vitest config uses `pool: 'forks', poolOptions: { forks: { singleFork: true } }` — always restore.
- A product SKU and a `DocumentTemplate` code are both unique: fixtures that repeat a price or create two templates need a counter in the generated value.
