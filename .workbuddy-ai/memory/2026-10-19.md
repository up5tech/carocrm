## Decisions worth remembering

- Module has **no metadata entity** in VC.0–6: communication data lives in dedicated tables
  (documented in the audit §6); the CRM `Call` Activity remains the user-facing call record.
- Event namespace is `voiceCommunications.*` (camelCase), because the plan's hyphenated
  `voice-communications.*` fails the platform `EVENT_TYPE` regex.
- MarketingAutomation consent is email-only (`channel = ['Email']`), so this module owns non-email
  consent/suppression.
- No phone library is installed and `pnpm add` is blocked in this environment; `phone-number.ts`
  is a conservative E.164 normalizer behind a `PhoneNumberNormalizer` seam.
- `ENCRYPTION_KEY` must be set for provider secrets; the integration suite sets it before `bootApi`.
- Kysely `RawBuilder` has no `executeTakeFirst(db)`; use `(await sql\`…\`.execute(db)).rows[0]`.
  A careless regex rewrite of that pattern corrupted several statements — repaired manually.
- Validation errors surface as HTTP **422**, not 400, in this platform.

## 19-VC.7–19-VC.11 (call sessions, click-to-call, popup, SMS, WhatsApp)

- Migration 052: `idempotency_key` on `voice_call_sessions`/`voice_messages` (partial unique) +
  `voice_whatsapp_templates` table.
- `voice-call.service.ts`: click-to-call (ACL → policy → session row → adapter), one session per
  `(account, provider_call_id)`, `advanceCallState` never regresses, one `Call` Activity created
  lazily on the first accepted state and updated through `EntityCrudService` (so audit/stream/ACL
  apply). Notes append to `description`; links use `accounts`/`contacts`/`users` relations.
- `voice-call-notification.service.ts`: one `notifications` row per call/recipient — assigned user,
  else the endpoint team's members; payload is the number only; dedup `voiceCall:<session>:ringing`.
- `voice-messaging.service.ts`: durable send (idempotency key, queued → sent/failed, policy checked
  twice), inbound materialization (unique provider id), monotonic `advanceMessageState`, internal
  notes never reach an adapter, media recorded as attachment references.
- `voice-whatsapp-template.service.ts`: local approval status + language + `{{n}}` variable
  validation, wired into policy; rejected/unapproved templates cannot be used.
- Simulator now declares whatsapp send/receive/templates and **requires** `sandboxRecipients`; every
  destination outside the allowlist is `invalid_recipient`. It never returns `delivered`.
- Tests: domain 35, base 24, calls 9, messaging 10 (78 total). `pnpm typecheck` and ESLint clean.
- Gotchas: platform error body is `{ error: { code, message, details } }`; policy `refusals` live in
  `error.details.refusals`. Account deletion is RESTRICTed by conversations/sessions, so test cleanup
  deletes those first. A freshly created session must not early-return from `applyCallEvent` or the
  incoming-call notification never fires.
