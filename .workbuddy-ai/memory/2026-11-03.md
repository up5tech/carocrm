Registry 15 → **20 keys**. All five are `effectClass: 'read'`, `requiresApproval: false`.

### Decisions worth remembering

- **`crm_stale_records` is owned by `ai-agents`, not a domain module.** §9.4's registration table did
  not name an owner. It reads the generic `entity_records` / `stream_items` store through the shared
  record ACL — no domain module owns that store, and putting it in one would create a reverse edge.
- **The ACL has to be translated into SQL by hand.** `AclApiService.recordPredicate()` returns a
  *predicate*, not SQL. The translation lives privately in `entity/entity-record.store.ts`
  (`aclSql` / `aclSqlForAlias`, plus `portalVisibilitySql` / `projectScopeSql`); the tool replicates
  it so a list and the tool decide identically.
- **An entity the caller has no grant for is safe.** `roleLevel()` falls back to `'no'` when neither
  an explicit entity entry nor the `*` wildcard exists → `denyAll` → constant-false SQL. So the
  free-form `entity` argument cannot reach records the caller may not read.
- `crm_lead_score` exposes `historyLimit` as **optional** (a second query the model did not ask for).
- `crm_customer_health` accepts an `accountId` as well as a `profileId` and resolves the profile first.
- `crm_case_context` returns `csat: null` (not an error) for a portal caller, who may not read results.
- `crm_run_report` with no `reportId` **lists** the reports the caller may run — the model needs the
  id before it can run anything.

### Traps hit (both cost real time)

- **Barrel ↔ contribution cycle.** A contribution class that lives in `ai-agents` must import
  `AIToolRegistry` from `./ai-agent-tools.js`, **not** from `./index.js`. The barrel imports the
  contribution, so importing the barrel back leaves the class `undefined` at runtime and Nest fails
  with `UndefinedDependencyException` (arg index [0]). The three domain contributions may import the
  barrel safely (no cycle), but the direct import is the safe habit.
- **`stream_items` columns are `entity_type` / `entity_id` / `is_deleted`** — *not* `parent_type` /
  `parent_id` / `deleted_at`. The plan's wording implied the latter.
- **A test that points the default AIAgents provider at its own fake provider must restore the
  `aiAgents` `app_settings` row.** Leaving a dangling `provider.defaultKey` makes
  `GET /api/v1/AIAgents/action/health` answer `ok: false` for every later run — it broke
  `ai-agents.test.ts` until the row was restored. Capture the row before the change and restore it in
  `afterAll`; `""` is the "unset" value the health service understands.
