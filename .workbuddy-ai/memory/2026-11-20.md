# 2026-11-20

## Phase 25.7 — bounded multimodal input (implemented, not committed)

Implemented ≤10 already-uploaded attachment references on CRM Chat turns and AIAgents runs.

- Core seam: `runs/attachments.ts` validates `fileId` lists, MIME (PNG/JPEG/PDF), 10MB/file cap,
  dedupe, and shapes metadata through `boundRecord`/`promptSafe` as untrusted prompt data.
- `AttachmentService.getById` ACL is checked at run creation (`runs/lifecycle.ts`) and again
  before every model call (`runs/transcript.ts`); a revoked file finishes the run as
  `blocked_by_policy` / `attachment_not_accessible` without a provider call.
- Extracted transcript construction into `runs/transcript.ts` to keep `runs/executor.ts` below the
  1,500-line ceiling (now ~1,383 lines).
- Vendor-neutral contract gained `AIProviderRequest.attachments` with bounded metadata only, no
  bytes. Gateway fails closed for invalid bounds or adapters without `imageInput`; real adapters
  stay `false`, fake is `true`, records ids in `safety.attachmentIds` and returns a stable text
  description.
- Run input JSON now stores bounded attachment metadata; view/turn status/message `content_meta`
  expose it. CRM Chat composer uploads files through the existing attachment API and sends ids;
  history renders non-clickable file-name tags (no ACL bypass).
- No migration. AIAgents module version 1.8.0. Docs updated: capability matrix row 5, plan status,
  README, CHANGELOG, PLAN.md, SPEC.md, compatibility doc, CRM Chat contract, api-spec.

Tests added (not run per `AGENTS.MD` §4): pure attachment bounds/injection test, fake adapter and
gateway capability tests, API ACL/revocation/prompt integration tests, CRM Chat DTO bound test,
web message rendering test.
